## 4. 数据流设计

### 4.1 状态管理

**文档管理流程**：
```
用户操作 → documentStore action → documentService → IndexedDB
                ↓
          更新 store 状态 → UI 重渲染
```

**打字练习流程**：
```
键盘输入 → practiceStore.handleInput()
              ↓
    ┌─────────┴─────────┐
    ↓                   ↓
 字符正确            字符错误
    ↓                   ↓
 前进到下一字符     标记错误，阻止前进
    ↓                   ↓
    └─────────┬─────────┘
              ↓
      更新统计数据 (KPM, 错误率)
              ↓
      检查是否完成 → 是 → 保存记录，跳转结果页
```

## 5. 关键设计决策

### 5.1 字符输入处理

- **背景**：需要实现逐字符对照输入，错误时阻止前进
- **方案**：使用隐藏 input 捕获键盘事件，逐字符比较
- **理由**：兼容性好，可处理各种键盘输入（包括特殊字符）

### 5.2 统计计算

- **背景**：需实时显示 KPM 和错误率
- **方案**：
  - KPM = (正确字符数 / 已用时间分钟数)
  - 错误率 = (错误次数 / 总击键次数) * 100%
- **理由**：符合 PRD 定义，与主流打字软件一致

### 5.3 存储策略

- **背景**：数据需持久化到浏览器
- **方案**：使用 Dexie.js 封装 IndexedDB
- **理由**：
  - 原生 IndexedDB API 繁琐，Dexie 提供简洁的 Promise API
  - 支持 TypeScript 类型推导
  - 提供 React Hooks 集成

## 6. 开发规范

### 6.1 代码规范

- **命名**：组件 PascalCase，函数/变量 camelCase，常量 UPPER_SNAKE_CASE
- **组件**：函数组件 + Hooks，单文件不超过 200 行
- **类型**：优先使用 interface，导出类型统一放 types/

### 6.2 Git 规范

- **分支**：main (生产) / dev (开发) / feat/xxx (功能)
- **提交格式**：`type: description`
  - feat: 新功能
  - fix: 修复
  - refactor: 重构
  - docs: 文档
